## 1. 文档范围

本稿根据用户提供的产品讨论整理，作为产品设计审核依据。已明确的方向与新增设计建议分开描述；建议及待确认事项不代表已经作出决定。本文不声明功能已经实现，也不将示例成绩视为真实学生数据。

## 2. 产品定位与目标

产品面向学习 ICT 的学生，将学习内容、概念理解、练习、表现分析与学习规划连接成一个持续调整的学习系统。

核心价值主张：

> 把“理解知识—练习—发现弱点—制定计划—再次学习”连成一个能够持续自我调整的 ICT 学习闭环。

产品解决三个问题：

- 学生在视频、练习软件和学习计划软件之间切换，学习记录与后续行动难以衔接。
- 学生缺少对自身薄弱知识点的客观认识，难以合理分配学习时间。
- ICT 的抽象概念仅靠定义或静态内容难以理解，需要能够展示结构、关系与变化过程的表达方式。

具体课程、考试体系、学生年龄和使用平台尚待确认。

## 3. 已明确的学习闭环

**视频学习 → 概念可视化 → 练习 → 表现分析 → AI 学习计划 → 再次练习**

```mermaid
flowchart LR
    V[视频学习] --> C[概念可视化]
    C --> Q[练习]
    Q --> A[表现分析]
    A --> P[AI 学习计划]
    P --> L[按计划再次学习]
    L --> Q
```

系统依据新的练习结果更新建议和学习时间分配。各模块需要共享知识点与学习记录，避免成为互不关联的独立功能。

上述流程是核心学习路径；是否允许学生跳过视频、直接练习或自主调整顺序，属于待确认的交互规则。

## 4. 核心功能设计

### 4.1 视频与学习内容

提供与 ICT 知识点关联的视频内容。理论知识结合视频、笔记与测验帮助学习。

设计建议：每个学习内容标注对应知识点，并关联可视化与练习入口。视频来源、版权、托管方式及是否使用 YouTube 尚待确认；现有讨论对 YouTube 的提及是学习渠道比较，不代表已经选定集成方案。

### 4.2 ICT 概念可视化

重点是帮助学生建立概念模型，呈现结构、关系和动态过程。

| 内容领域 | 已明确的表达方向 | 学习目的 |
| --- | --- | --- |
| Hardware（硬件） | 视频与 3D PC 拆解，展示 CPU、RAM、SSD 和主板的位置与关系 | 理解计算机组成及部件关系 |
| Programming（编程） | 逐行执行、变量变化、循环过程及错误出现的可视化 | 理解代码执行和调试过程 |
| Networking（网络） | 展示数据包从设备到路由器再到服务器的移动过程 | 理解网络传输路径与过程 |
| Database（数据库） | 表与关系的可视化 | 理解数据组织及表之间的关系 |
| 理论知识 | 视频、笔记与测验 | 理解并巩固基本概念 |

这构成多模态学习体验：根据知识特点选择教学方式，而非把所有内容都转化为选择题。

设计建议：可视化允许学生控制节奏，并提供解释文字。具体交互方式、编程语言、硬件模型精度及网络模拟范围尚待确认。

### 4.3 练习与错题

练习用于检验理解程度，并产生表现分析所需的数据。系统计算准确率、薄弱知识点与错题信息。选择题可以是题型之一，但不应默认成为所有领域唯一的学习方式。

设计建议：题目关联知识点，保存作答结果与练习时间，支持从错题返回对应学习内容。题型、评分规则、题库来源以及是否保存答题耗时尚待确认。

### 4.4 表现分析

由程序依据练习记录计算客观指标，为规划提供依据。

已明确的指标方向包括：

- 准确率。
- 薄弱主题或知识点。
- 错题记录。
- 再次练习后的成绩变化。

例如，假设练习结果为 Networking 43%、Database 82%、Programming 61%，系统应识别 Networking 为需要优先关注的领域。这些百分比仅是说明优先级逻辑的示例。

设计建议：同时展示题目数量和数据时间范围，避免把少量题目的成绩当成稳定能力评价。聚合方式、弱项阈值、近期成绩权重和跨难度比较规则尚待确认。

### 4.5 AI 个性化学习计划

计划以以下输入为基础：

**测验结果 + 薄弱主题 + 可用学习时间 + 考试日期 → 个性化学习建议**

职责分工：

| 程序负责 | AI 负责 |
| --- | --- |
| 计算准确率、识别弱项、整理错题和成绩变化 | 将结构化学习数据转化为学生容易理解、能够执行的学习计划 |

AI 的核心角色是基于学习数据生成规划建议。独立聊天机器人不是本稿已确认的产品需求。

设计建议：计划包含学习主题、推荐内容、练习任务、预计时间与推荐理由；生成结果校验总时间是否超出学生可用时间。优先级规则、考试日期缺失时的处理和 AI 服务选型尚待确认。

### 4.6 持续自适应调整

学生执行计划并再次练习后，系统重新分析表现，调整下一轮建议。

例如，Networking 从 45% 提升到 68% 后，系统可以减少该领域的基础学习安排，并根据其他领域的表现重新分配时间。该示例不代表已经确定的调整阈值。

目标循环：

**表现 → 建议 → 学习 → 新表现 → 更新建议**

设计建议：保存计划版本与调整原因，方便学生理解变化。更新触发条件、频率及手动修改计划的规则尚待确认。

## 5. 代表性学生使用流程

以下是根据已明确功能整理的流程建议，具体页面和先后顺序待审核：

1. 学生填写可用学习时间和考试日期。
2. 完成初始练习，获得各主题的表现分析。
3. 系统依据真实练习数据生成学习计划。
4. 学生按计划观看视频并使用相应概念可视化内容。
5. 学生完成关联练习，查看成绩与错题。
6. 系统分析新的表现，更新薄弱主题与后续计划。

待确认：缺少练习记录时是否先进行诊断测验，以及学生能否直接选择主题开始学习。

## 6. 数据与模块衔接建议

为支持闭环，建议以统一知识点标识关联以下信息：

| 信息 | 用途 |
| --- | --- |
| 知识点与领域 | 连接内容、题目、表现分析和计划 |
| 视频、笔记与可视化资源 | 提供对应知识点的学习入口 |
| 题目与作答记录 | 支持评分、错题与表现计算 |
| 表现汇总 | 作为规划依据并展示变化 |
| 学习时间与考试日期 | 约束计划安排 |
| 计划及更新记录 | 支持任务执行和调整说明 |

这只是逻辑数据设计建议，尚未确定数据库结构、接口或技术栈。

## 7. 核心竞争优势

1. **完整学习闭环**：连接理解、练习、分析与规划，并用后续成绩继续调整。
2. **真实表现驱动规划**：根据学生实际薄弱领域分配学习优先级。
3. **ICT 概念可视化**：通过部件关系、代码执行、网络流动和表关系帮助建立概念模型。
4. **有明确职责的 AI**：在程序计算的客观数据基础上生成易执行的建议。
5. **多模态教学**：不同知识领域采用适合自身特点的学习方式。
6. **持续适应学习进展**：建议随新成绩更新，学习路径随进步而变化。

用于 proposal 的简洁表达：

> 本应用的竞争优势在于把多媒体学习、交互式可视化、表现分析与 AI 学习规划整合为一个自适应学习闭环。系统识别学生实际的薄弱知识点，将抽象 ICT 概念可视化，并根据学习进展持续调整计划。

三个主要卖点：**ICT 概念可视化、基于真实表现的个性化学习计划、完整的自适应学习闭环**。

这些是拟议产品的差异化方向；本稿未提供竞品研究或学习效果实验，不能据此宣称已证明优于现有产品。

## 8. 首版范围建议与验收方向

首版建议优先打通一条完整闭环，再逐步扩展内容覆盖。Hardware、Programming、Networking 和 Database 均属于产品方向；各领域首版覆盖深度尚待审核。

建议的验收方向：

- 同一知识点能够连接学习内容、可视化、练习和表现记录。
- 练习评分与准确率能够依据作答记录复算。
- 学习计划引用已有表现数据，并说明关注某个主题的原因。
- 计划安排不超出学生填写的可用学习时间。
- 再次练习后，表现分析使用新数据，计划按已批准的规则更新。
- 可视化能够正确表达选定概念，并可通过对应理解题检验学习目标。

以上属于建议的验收条件，不是已完成的测试或已经批准的完整需求。
